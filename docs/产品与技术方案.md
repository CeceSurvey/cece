**架构决策摘要**

选择移动端 Web App 而非原生 Android 的原因：
1. 横竖屏双布局用 CSS 媒体查询一次实现，原生需维护两套布局文件；
2. 零安装、扫码即用，教师分发成本从"装机 40 台"降为"发一个链接"；
3. 保留 Capacitor 打包路径，需要真 APK 时可随时产出，不锁死方案。

**技术债务清单**

| 项 | 影响 | 建议处理时机 |
|----|------|--------------|
| 存档存储在浏览器 localStorage | 清理浏览器数据会丢失 | v1.1 增加自动导出提醒 / 改用 IndexedDB + 文件系统访问 API |
| 无多用户与云同步 | 换设备需手动导入导出 | 视是否需要学生交作业而定 |
| 坐标值仅做 parseFloat 解析 | 输入 `1,5` 会被解析为 1 | v1.1 增加输入规范化 |
| 未做数据合法性校验 | 坐标异常值（如 1e9）会把图形压扁 | v1.1 增加范围提示 |

## 一、需求与平台选型（Phase 1）

### 1.1 需求三要素

| 要素 | 内容 |
|------|------|
| 做什么 | 一套支持存档管理的全站仪测量点位记录与实时成图工具 |
| 面向谁 | 土木工程测量课程的任课教师与实训学生 |
| 核心目标 | 让学生在录入观测数据的同步看到点位分布，及时发现布点与观测问题 |

### 1.2 平台选型对比

| 维度 | 原生 Android | **移动端 Web App（选定）** | 桌面软件 |
|------|--------------|---------------------------|----------|
| 横竖屏适配 | 两套布局代码 | CSS 媒体查询，一套代码 | 意义弱 |
| 分发成本 | 需打包签名、逐台安装 | 发链接 / 扫码 | 需安装包 |
| 本地存档 | 需文件读写权限 | localStorage + 文件导入导出 | 无限制 |
| 现场手持体验 | 好 | 好（PWA 全屏） | 差 |
| 开发与迭代速度 | 慢 | 快 | 中 |

**结论**：选移动端 Web App。理由是按"分发成本 + 迭代速度"排序，教学场景中教师最痛的是"给 40 个学生装 App"，而不是性能。

### 1.3 MVP 范围界定

**必须当期**
- 五个页面与完整路由
- 存档增删改查 + 只读模式
- 表格录入、拖拽排序、动态增行
- 平面坐标实时成图 + 点号标注
- 横竖屏自适应 + 图形缩放自适应
- 自动保存

**明确延后**
- 云同步与账号体系
- 导线平差、闭合差计算
- 点位连线成图、面积量算
- 数据导出为 Excel / DXF

### 2.2 关键交互设计决策

**为什么用滑块拖拽而不是输入序号排序**
测量点位顺序对应观测顺序，学生调整顺序时的心理模型是"把这一行挪上去"，而非"把序号从 3 改成 1"。拖拽与心智一致，且不会产生重复序号。

**为什么图形保持等比例**
平面坐标图一旦 x/y 比例不同，点位形状会失真，学生会得出错误的图形判断。因此缩放系数取 x/y 两个方向的较小值，宁可留白也不变形。

**为什么主动缩放后停止自动跟随**
学生放大查看某几个点时，若每改一个数值就跳回全图，操作会频繁被打断。因此手动缩放后进入"锁定视角"，由「自适应」按钮主动恢复。

### 2.3 连线列的设计取舍

**存行 id 而不存点号**

连线在数据层记录的是目标行的 `id`（`row.link = 'r_xxx'`），不是点号文本。原因：

- 学生拖动排序后，行的位置变了但 id 不变，连线自动跟随，不会错位
- 学生中途修改点号（如 A2 改成 A2′），连线关系不受影响，显示文本自动更新
- 若存点号文本，上述两种操作都会让连线指向错误的点或直接失效

代价是导入存档时需要做一次 id 重映射（旧存档的行 id 会整体重建）。已实现：导入时建立 `oldId → newId` 映射表，再回填 link。

**为什么需要"透明 select"方案**

需求要求"选中后格内不显示任何字"，但原生 `<select>` 的选项文字会直接渲染在单元格里，无法在选中"不连线"时显示空白。

解决方案：用一个 `opacity: 0` 的原生 `select` 铺满单元格接收点击，真正的显示由下层 `<span>` 控制。这样既保留了移动端系统选择器的原生手感（滚轮/弹层、触控命中区域大），又能完全控制格内显示内容。

**连线的绘制层级**

连线绘制在网格与坐标轴之上、点位之下。这样线不会盖住点号的白色描边，视觉上始终是"点压在线上"，与测量图的习惯一致。

## 三、技术架构（Phase 1）

### 3.1 分层

```
┌─────────────────────────────────────────┐
│  视图层   index.html（页面骨架）           │
│           styles.css（响应式与主题）       │
├─────────────────────────────────────────┤
│  逻辑层   app.js                          │
│    ├─ 路由      hash 路由 + 屏幕切换       │
│    ├─ 存储      Store（localStorage 封装） │
│    ├─ 表格      renderRows / buildRow     │
│    ├─ 排序      Pointer Events 自定义拖拽  │
│    ├─ 绘图      SVG 字符串渲染 + 视图变换  │
│    └─ 手势      Pointer 多点 + 滚轮        │
├─────────────────────────────────────────┤
│  数据层   localStorage                    │
│           cece:index           存档索引    │
│           cece:project:<id>    单档全量数据 │
└─────────────────────────────────────────┘
```

### 3.2 关键实现说明

**渲染策略：不用框架，用「结构重绘 + 局部更新」分离**

- 结构性变化（增行、排序、加载存档）→ 重建 DOM
- 数值变化（输入字符）→ 只更新数据模型并重绘 SVG

这样避免了"输入一个字符导致输入框失焦"的经典问题，也让重绘成本保持在毫秒级。

**拖拽排序实现**

使用 Pointer Events 而非 HTML5 Drag & Drop（后者在移动端支持差）。按下滑块时对指针做 capture，拖动过程中：

- 当前行 `translateY` 跟手
- 其余行按目标索引计算 `translateY(±rowH)` 让位，带 160ms 过渡
- 松手后重排数组并重绘

**绘图实现**

SVG 而非 Canvas。点数量在几十量级，SVG 的文字标注、清晰度、可访问性都更优。坐标映射关系：

```
screenX = plotCenterX + (E - cx) * scale
screenY = plotCenterY - (N - cy) * scale
```

其中 `scale` 为像素/米，`(cx, cy)` 为视野中心的地图坐标。刻度步长采用 1/2/5 × 10ⁿ 的"漂亮刻度"算法。

**横竖屏适配**

`@media (orientation: landscape) and (min-width: 640px)` 切换工作区 flex 方向，同时监听 `resize` / `orientationchange` / `visualViewport.resize` 重新计算绘图尺寸。加 `min-width` 是为了避免桌面窄窗口误触发左右分栏。

### 3.3 性能与容量

| 指标 | 实测 |
|------|------|
| 首屏可交互 | < 100ms（本地，无网络依赖） |
| 输入响应到图形刷新 | 单帧内（requestAnimationFrame） |
| 单存档容量上限 | 约 5MB（localStorage 上限），等价数千行 |
| 建议行数 | ≤ 100 行（超出后拖拽滚动体验下降） |

| 风险 | 影响 | 预案 |

## 八、版本变更记录

### v3.0.3（2026-11-11）

**图面交互修复：连线编辑判定、手势阈值、图表区域文本选择**

- **连线编辑「必须长按」根因**：点按判定原为 `!p.moved && pointers 为空 && Date.now() - p.t < 700`，其中 700 ms 时长上限会让按得稍慢的点击被直接丢弃，表现为「轻点无效、按住才弹编辑框」。改为只以「按下到抬起之间无拖动」为准，与按住时长无关
- **手势阈值统一为 `TAP_SLOP = 8` px**：原 `pointermove` 位移 1 px 即平移视图、而 `p.moved` 需 8 px 才置位，导致轻微手抖时视角已漂移并误置 `ws.view.manual`（丢失自适应），一并修正；平移首次越过阈值时把起点对齐到当前位置，避免视角一次性跳变
- **连线命中容差**：默认 11 px，已选中某条线时放宽到 22 px（`LINK_HIT_TOL_PICKED`），让「再点它一次」可靠触发编辑
- **双指缩放保护**：新增 `chart.multiTouch`，手势序列中一旦出现第二根手指，序列收尾时不参与点按判定，避免缩放后误选连线或点位
- **图表区域禁用文本选择**：`.chart-wrap` / `#chart` 增加 `user-select:none`、`-webkit-touch-callout:none`，长按不再选中 SVG 内的点号、坐标注记与「N↑ / E→ 单位：m」标注；同时阻止 `contextmenu`，避免长按弹出系统菜单打断操作
- 提示文案统一为「再点它一次」，与实际行为一致；版本号 3.0.2 / 30002 → 3.0.3 / 30003，Service Worker 缓存名同步为 `cece-v3.0.3`

### v2.0.0（2026-11-08）

**性能：修复点位较多时的卡顿**

> 结论：卡顿来自网页逻辑，与 APK 无关。APK 只是一个 WebView 壳，不含任何逐行渲染代码。

测量后实测 100 点以上开始明显变慢，定位到三处 O(N²) 实现：

| 位置 | 原因 | 规模（120 点 / 200 点） | 处理 |
|------|------|------------------------|------|
| 连线列 | 每行一个原生 `<select>`，每个 select 含全部点号，合计 N² 个 `<option>` | 14 400 / 40 000 个 option | 删除连线列，改为图上点选连线 |
| `refreshLinkOptions` | 每次按键后的重绘都会重建所有 select 的 option | 每次按键重建 N² 个节点 | 随连线列一并移除 |
| `renderRows` / 增加一行 | 增行时整表重建；标注避让为 O(N²)×8 次矩形相交 | 增行 285 ms / 648 ms | 增行改为追加单行；避让改用网格哈希，O(N) |

另外把 SVG 由"每次重绘 innerHTML 重建"改为节点池复用 + 属性更新，平移/缩放按 rAF 合帧。

真机（Edge/Chromium 内核，200 点）实测：打开 8.7 ms、一次按键 0.2 ms、单帧重绘 4.1 ms、增加一行 5.5 ms、文档元素 5 240（旧版 45 603）。

同环境前后对比（jsdom，120 点，排除设备差异）：打开工作 418 → 126 ms，一次按键 40.5 → 1.6 ms，增加一行 464 → 42 ms，文档元素 17 843 → 3 344，`<option>` 节点 14 400 → 4。200 点时增行仍为 37 ms，与点数基本无关（旧版随点数平方增长）。
