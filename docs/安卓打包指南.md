# 安卓打包指南

> **一句话结论**：APK 已经打好了，位置在 `dist/测策-v2.7.0.apk`（138 KB），直接装到手机/平板即可。
> 本文档说明安装方法、工程结构，以及以后改了网页代码怎么重新打包。

---

## 一、为什么不用 Capacitor / Android Studio

本项目是纯静态网页，没有 npm 依赖、不联网、不调原生硬件。为此采用了**手写原生 WebView 壳**的方案，而不是 Capacitor / Cordova：

| 方案 | 包体 | 依赖 | 需要 Android Studio | 构建耗时 |
|------|------|------|---------------------|----------|
| **本方案（原生 WebView 壳）** | **138 KB** | 仅 JDK + build-tools | 否 | ~8 秒 |
| Capacitor | 4–8 MB | Node + Gradle + AGP | 建议需要 | 数分钟（首次下载依赖更久） |
| Cordova | 5–10 MB | Node + Gradle | 建议需要 | 数分钟 |

对这样一个单页工具来说，Capacitor 带来的体积和工具链负担没有对应收益。壳代码只有 1 个 Java 文件（`android/src/com/chaiyichai/cece/MainActivity.java`），约 400 行，全部逻辑可读可控。

## 二、安装到设备

**方式一：数据线（推荐）**

1. 手机/平板开启「开发者选项 → USB 调试」
2. 安装 platform-tools 后执行：
   ```bash
   adb install -r "dist/测策-v2.7.0.apk"
   ```
   或直接把 APK 拷进设备，用文件管理器点击安装。

**方式二：微信/QQ 传文件**

发送到「文件传输助手」，在手机上点开安装。需要允许「安装未知来源应用」。

**首次安装会被系统拦截**：因为签名是自签名证书（不是应用商店证书），系统会提示"未经检测的应用"或"存在风险"，选择「仍然安装」即可。这是自签名 APK 的正常现象。

## 三、工程结构

```
android/
├─ AndroidManifest.xml                包名、版本号、权限、Activity 声明
├─ src/com/chaiyichai/cece/
│   └─ MainActivity.java              原生壳全部逻辑
├─ res/
│   ├─ values/{strings,colors,styles}.xml   应用名、主题色、状态栏配色
│   ├─ drawable/ic_launcher_background.xml  图标背景（品牌色渐变）
│   ├─ drawable/ic_launcher_foreground.xml  图标前景（坐标轴矢量图）
│   ├─ drawable/ic_launcher_monochrome.xml  Android 13+ 主题图标
│   ├─ mipmap-anydpi-v26/                   自适应图标（Android 8.0+）
│   └─ mipmap-*/ic_launcher*.png            各密度兼容位图（Android 7.0–7.1）
├─ tools/
│   ├─ make-icons.js                  由 icon.svg 生成各密度图标（需 sharp）
│   └─ patch-web.py                   给 app.js 注入原生导出钩子
├─ keystore/chaiyichai-release.jks    签名密钥库（务必保留）
├─ store/ic_launcher_512.png          512×512 图标，将来上架用
└─ build.sh                           一键构建脚本
```

**关键设计**（都在 `MainActivity.java` 里，改动前请先读注释）：

| 设计点 | 原因 |
|--------|------|
| 用 `https://appassets.androidplatform.net` 虚拟域名加载 assets | 获得"安全来源"，localStorage 才会稳定落盘。用 `file://` 加载时各版本 WebView 的本地存储行为不一致，存档可能丢 |
| 原生导出 `CeceAndroid.saveArchive()` | 浏览器里的 `<a download>` 在 WebView 中不生效，导出的存档 / CSV 会静默失败 |
| 原生存图 `CeceAndroid.saveImage()` | 成果图与智能纸图导出，存进相册 `Pictures/测策`；缺此方法会退化为页面内长按预览 |
| 接管文件选择器（`onShowFileChooser`） | 否则「导入存档」按钮点了没反应 |
| `configChanges` 含 `orientation\|screenSize` | 横竖屏旋转不重建 Activity，输入到一半的表格不会被清空 |
| 返回键分级回退 | 工作区 → 存档管理 → 首页 → 退出，避免误触把正在编辑的存档关掉 |
| `setTextZoom(100)` | 系统字体放大会撑破测量表格的列宽 |

## 四、修改网页后重新打包

改完 `index.html` / `app.js` / `styles.css` 后，在项目根目录执行：

```bash
bash android/build.sh
```

产物覆盖 `dist/测策-v<版本号>.apk`。构建脚本会自动：

1. 把 6 个前端文件复制进 `assets/www/`
2. 给 `app.js` 副本注入原生导出钩子（不改动源文件，Web 版行为不变）
3. `aapt2` 编译资源 → `javac` 编译 Java → `d8` 转 DEX
4. `zipalign` 对齐 → `apksigner` 签名 → 校验
5. 输出版本号、签名指纹与产物路径

**工具链依赖**：

| 组件 | 版本 | 说明 |
|------|------|------|
| JDK | 17 | 需含 `javac` / `keytool` |
| Android build-tools | 35.0.0 | 提供 `aapt2` / `zipalign` / `d8.jar` / `apksigner.jar` |
| Android platform | android-35 | 仅需其中的 `android.jar` 作编译期引用 |

当前工具链放在 `D:/_apkbuild/`，脚本会自动探测。换机器时设置环境变量即可：

```bash
export ANDROID_BUILD=/path/to/toolchain   # 其下需有 jdk*/ 与 sdk/*/
export JAVA_HOME=/path/to/jdk-17
bash android/build.sh
```

不需要 Gradle，不需要 Android Studio，也不需要联网（首次装工具链除外）。

## 五、升级版本号

版本号以 `android/AndroidManifest.xml` 为唯一来源，同时改两处：

```xml
android:versionCode="10301"      <!-- 必须递增，否则无法覆盖安装 -->
android:versionName="1.3.1"      <!-- 显示给用户看 -->
```

`versionCode` 规则建议：`主版本×10000 + 次版本×100 + 修订号`，当前 `30003` 对应 `3.0.3`。

改完后同步更新 `index.html` 里「关于程序」页和首页底部的版本号文字（这两处是硬编码的）。

| 项目 | 值 |
|------|-----|
| 密钥库 | `android/keystore/chaiyichai-release.jks` |
| 别名 alias | `chaiyichai` |
| 密码 | `chaiyichai2026` |
| DN | `CN=ChaiYiChai` |
| 有效期 | 30 年（10950 天） |

**必须遵守**：

- **这个文件丢了，就无法再发布能被系统识别的更新**。已安装的旧版必须卸载才能装新版，而卸载会清空全部存档。请把 `android/keystore/` 和本文档一起备份到网盘。
- 想换密码：删掉 jks 文件后重新执行 `build.sh`，脚本会自动生成新密钥库（同时也要改 `KS_PASS` 环境变量）。但换密钥库 = 换应用身份，老用户需卸载重装。
- 想上架应用商店：自签名证书**不能**直接上架。需按商店要求重新生成密钥并由商店体系签名，同时要补隐私政策、软著等材料。

## 七、数据须知

| 事项 | 说明 |
|------|------|
| 存储位置 | APK 的 localStorage 在 WebView 私有目录中，与浏览器数据**完全隔离** |
| 迁移存档 | 装 APK 前先在浏览器版里「导出」，装好后在「存档管理 → 导入」恢复。反过来同理 |
| 卸载 | 会清空 WebView 数据，**包括全部存档**。卸载前务必导出备份 |
| 覆盖安装 | 同签名的覆盖安装保留数据；换签名视为新应用，数据不保留 |
| 清理缓存 | 系统设置里「清除应用数据」等同卸载效果，存档全部丢失 |
| 导出位置 | 存档 JSON 与成果 CSV 写入 **`下载/测策/`**；成果图 / 智能纸图写入相册 **`Pictures/测策/`**。均可在文件管理器或相册中找到，也可通过微信/QQ 转发 |
| 备份建议 | 重要测量数据定期导出。程序本身没有云端，这是唯一的异地备份手段 |

## 八、兼容性

| 项目 | 值 |
|------|-----|
| 包名 | `com.chaiyichai.cece` |
| 最低系统 | Android 7.0（API 24） |
| 目标系统 | Android 14（API 34） |
| 编译 SDK | API 35 |
| 屏幕 | 手机、平板、横竖屏、折叠屏均支持 |
| 权限 | 仅 `INTERNET`（见下） |
| 离线 | 完全离线可运行 |

关于 `INTERNET` 权限：WebView 加载 `https://appassets.androidplatform.net` 这一虚拟域名时，部分 WebView 版本会校验该权限，缺失可能导致白屏。所有请求都在 `shouldInterceptRequest()` 里从 APK 内部直接返回，**不会产生任何真实网络连接**，代码中也没有任何联网逻辑。若你确认目标设备无此问题，删掉 `AndroidManifest.xml` 里那行 `uses-permission` 重新打包即可，权限列表将为空。

## 九、常见问题

**Q：安装时提示「解析软件包时出现问题」**
A：多为下载不完整或系统版本低于 Android 7.0。核对文件大小应为 141398 字节左右，SHA-256 见 `dist/校验信息.txt`。

**Q：装好后打开是白屏**
A：先确认设备系统 ≥ Android 7.0。若仍白屏，连数据线执行 `adb logcat | grep -i "chromium\|cece"` 查看报错，把日志发出来定位。

**Q：导出点了没反应**
A：`下载/测策/` 目录需要 Android 10+ 才会出现在文件管理器里。Android 7–9 上文件写在应用私有目录，路径会显示在提示文字中，可用 `adb pull` 取出。若设备是 Android 7–9 且频繁导出，建议升级系统或改用微信转发。

**Q：从 APK 里导出的存档，能在浏览器版导入吗？**
A：可以，两端格式完全一致（`.cece.json`），双向互通。

**Q：能不能既保留 APK 又保留 PWA？**
A：可以，两者数据独立但格式互通。PWA 更新更简单（改完刷新即可），APK 胜在有固定桌面图标和独立窗口。

**Q：想加「分享到微信」功能**
A：需要接入微信开放平台 SDK 并配置 AppID，会显著增加工程复杂度。当前用「导出到下载目录 + 微信手动发送」已能覆盖需求。
